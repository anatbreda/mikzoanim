# מקצוענים

מדריך בעלי מקצוע שנבנה אוטומטית מייצוא של קבוצת ווטסאפ.
חיפוש לפי **תחום** (אינסטלציה, חשמל, שיניים…) ולפי **שם**.

**האתר:** https://anatbreda.github.io/mikzoanim/

אתר סטטי לגמרי - בלי שרת, בלי מסד נתונים, בלי הרשמה ובלי תלויות חיצוניות.

## פרטיות

**שום דבר לא עוזב את המכשיר.** קובץ הייצוא מפוענח בדפדפן, התוצאה נשמרת
ב-`localStorage`, ואין באתר אף קריאת רשת. כל מי שפותח את הקישור מעלה את
הקובץ שלו ורואה רק אותו. הריפו הזה מכיל **קוד בלבד** - אין בו שמות ואין
מספרי טלפון.

## איך משתמשים

1. בווטסאפ: פרטי הקבוצה ← **ייצוא צ׳אט** ← **ללא מדיה**.
   כרטיסי אנשי הקשר נכללים כך ממילא — ווטסאפ לא מתייחס אליהם כאל מדיה
   כמו תמונה, וידאו או הודעה קולית — והקובץ יוצא קטן ומהיר להעלאה.
2. לפתוח את האתר ולגרור אליו את קובץ ה-ZIP.
3. בנייד כדאי להוסיף למסך הבית (שיתוף ← הוספה למסך הבית): זה נותן אייקון
   ופתיחה במסך מלא, ובסאפארי גם פוטר את האתר מהמנגנון שמוחק אחסון של אתרים
   שלא נכנסים אליהם כשבוע.

נתמכים ייצוא של אייפון ושל אנדרואיד, וסדר התאריך (יום/חודש מול חודש/יום)
מזוהה אוטומטית מתוך הקובץ.

## איך נקבע התחום

לכל כרטיס איש קשר נאספים עד ארבעה אותות בלתי תלויים:

| אות | מקור | ודאות בסיס |
|---|---|---|
| שם הכרטיס | ה-vCard עצמו: `FN`, `ORG`, `X-WA-BIZ-NAME`, `X-WA-BIZ-DESCRIPTION` | 0.85 |
| כיתוב | הודעה של מי ששלח את הכרטיס, עד 3 הודעות ו-10 דקות ממנו | 0.60 |
| בקשת המלצה | הבקשה האחרונה בקבוצה שכוללת שם מקצוע | 0.80 / 0.60 / 0.35 לפי מרחק |
| תגובה | הודעה של מישהו אחר מיד אחרי הכרטיס | 0.30 |

הוודאות הסופית היא הגבוהה מביניהם, בתוספת 0.07 לכל אות נוסף שהסכים.
כששני תחומים קרובים, הרשומה מסומנת כדו-משמעית ונכנסת לתור הבדיקה.

**כל שיוך נשמר עם הראיה שלו** - הטקסט המקורי, השעה והשולח - ומוצג בכרטיס
תחת "למה סווג כך?". אפשר לתקן כל שיוך ידנית, והתיקונים שורדים ייבוא חוזר.

### מה המערכת לא יכולה לעשות

ייצוא ווטסאפ **לא שומר מי הגיב למי**. אין בקובץ מטא-דאטה של ציטוט או תגובה,
ולכן אי אפשר לדעת בוודאות לאיזו בקשה כרטיס מסוים עונה. הקישור נעשה לפי
סמיכות בזמן ובסדר ההודעות, וזו הסיבה שכל שיוך מלווה בראיה גלויה.

שני כללים מטפלים במקרים שההיוריסטיקה הפשוטה נכשלת בהם:

- **מחפשים את הבקשה האחרונה, לא את ההודעה האחרונה.** כרטיס של שיננית יכול
  לשבת באמצע שרשור על סדנאות בישול, כשהבקשה הנכונה חמש הודעות אחורה.
- **שם איש הקשר עוצר את הסריקה.** אם הודעה סמוכה מזכירה את שם איש הקשר,
  זו ההודעה שהכרטיס עונה לה, ואין להמשיך אחורה לבקשה ישנה יותר.

## ביצועים

קבוצה ותיקה יכולה להגיע לעשרות אלפי הודעות ולמאות תמונות. שני דברים נבנו
בשביל זה:

- מהארכיון נפרסים **רק** קובץ הצ׳אט וכרטיסי אנשי הקשר. ייצוא של 114MB עם
  120 תמונות עולה ~7MB זיכרון במקום 114MB.
- לפני 600 בדיקות מילות המפתח עובר שער מהיר יחיד. 60,000 הודעות מסווגות
  ב-~0.75 שניות במקום ~4.7.

## כלים

```bash
node tools/selftest.js                 # 39 בדיקות על מקרי הקצה
node tools/extract-cli.js <ייצוא.zip>  # אותו מנוע, בלי דפדפן
node tools/extract-cli.js <ייצוא.zip> --evidence
```

`extract-cli.js` לא כותב קבצים, רק מדפיס - שימושי לאימות הסיווג מול הצ׳אט
המקורי לפני שמסתמכים עליו.

## מבנה

| קובץ | תפקיד |
|---|---|
| `js/util.js` | ניקוי סימני כיווניות, נרמול טלפון ישראלי |
| `js/professions.js` | טקסונומיית התחומים והתאמת מילות מפתח בעברית |
| `js/vcard.js` | פענוח `.vcf`, כולל החריגות של ווטסאפ |
| `js/zip.js` | קריאת ZIP דרך `DecompressionStream`, בלי ספריות |
| `js/whatsapp.js` | פענוח קובץ הצ׳אט להודעות |
| `js/classify.js` | איסוף האותות, ציון הוודאות והמיזוג לאנשים |
| `js/store.js` | `localStorage` והתיקונים הידניים |
| `js/app.js` | ניתוב ותצוגה |

כל מודול נטען גם בדפדפן וגם ב-`require` של Node, כדי שה-CLI והאתר ירוצו על
אותו מנוע ולא ייפרדו עם הזמן.
